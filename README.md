# CheatShqip

Android app for **English → Albanian** word translation and grammatical lookup. Type an English word, get ranked Albanian translations from a bundled offline dictionary, and tap through to a full grammatical detail view (noun gender, singular/plural forms, and a complete declension paradigm).

The whole app works **fully offline** — translation and word details are served by a pre-built SQLite dictionary (`dictionary.db`) that ships inside the APK. No ML Kit, no network dependency.

## Features

- **Offline English → Albanian translation** from a bundled 51,607-entry dictionary.
- **Relevance-ranked results** using SQLite FTS5 full-text search with a two-tier BM25 + corpus-frequency ranking (ADR 006, ADR 007) — exact translations surface before compounds, with frequency breaking ties.
- **Word detail screen** showing word kind and gender chips, singular/plural grammatical forms, and the full noun declension paradigm:
  - 5 cases (nominative, genitive, dative, accusative, ablative)
  - 4 declension sets (singular/plural × indefinite/definite)
- **Custom design system (`:tosk`)** — a token-based Compose component library with its own demo app (`:toskdemo`), light/dark theming.

## Architecture

The project follows **hexagonal (ports & adapters) architecture**, strictly enforced. `domain` knows nothing about Android, databases, or networks; `application` defines use-case and port interfaces; `adapter` implements them; `presentation` is MVVM with Compose.

```
UI (Compose)
  HomeScreen / WordDetailScreen
        │  state flows
  ViewModels (HomeScreenViewModel, WordDetailViewModel)
        │
  application/port/input         use-case interfaces
        │
  application/  TranslationService · AlbanianWordService
        │
  application/port/output        output-port interfaces
        │
  adapter/output/                adapters
        │
  DictionaryDatabase (Room + FTS5)
```

### Core data flow

**Translate** — `HomeScreen` → `GetWordTranslationSuggestionsUseCase` → `TranslationService` → `SqliteEnglishToAlbanianOutputAdapter` runs the FTS5 two-tier ranked query over `entry_fts.english` and returns up to 5 Albanian translations (capped in `TranslationService`).

**Word details** — `WordDetailScreen` → `GetAlbanianWordDetailUseCase` → `AlbanianWordService` → `RoomAlbanianWordDetailOutputAdapter` reads the entry by ASCII headword and builds an `AlbanianNounEntry`; `NounParadigm.from(baseForms)` derives the full declension table from the four noun base forms stored in the row.

### Domain model

Immutable value objects under `com.cheatshqip.domain`: `Word` (with Unicode diacritic normalization), `Translation`, `AlbanianWordDetail`, `AlbanianNounEntry`, `NounBaseForms`, `NounParadigm`, per-case declension values (`NominativeDeclension`, … `AblativeDeclension`), `GrammaticalDisplay`, `WordKind`, `WordGender`.

### Package layout

```
com.cheatshqip
├── domain/                    # business entities & value objects
├── application/
│   ├── port/input/            # use-case interfaces
│   └── port/output/           # output-port interfaces
├── adapter/output/            # Room + SQLite FTS5 adapters
├── di/                        # Koin module wiring
└── (root)                     # Compose screens, ViewModels, UI states, MainActivity
```

## The Bundled Dictionary Database

Translation and word details are served by `app/src/main/assets/dictionary.db`, a pre-built SQLite database (~37 MB, 51,607 entries) loaded by Room.

- Generated by the **`words/` Python pipeline** (`dict-builder`) — a separate project at `../words` that merges Uniparser Albanian morphology with Kaikki Wiktionary data into a schema-validated dictionary and emits SQLite.
- Exposes an FTS5 virtual table (`entry_fts`) indexed over `albanian_ascii`, `english`, and `gloss`, queried with raw SQL via `@RawQuery` DAO methods.
- Loaded with the **bundled SQLite driver** (`BundledSQLiteDriver`), which guarantees FTS5 support on every device regardless of the OS SQLite build. Because Room's `createFromAsset` is incompatible with a custom driver, the asset is copied into the app's database directory on first launch by `DictionaryDatabaseFactory` (ADR 004).
- The database embeds the Room **identity hash** — regenerating it must be done with `--room-identity-hash` from the exported schema (`app/schemas/.../1.json`) or the app crashes on launch.

### Regenerating the database

```bash
# 1. Export the Room schema and read the expected identity hash
./gradlew :app:kspProdDebugKotlin   # (or :app:kspDebugKotlin)
# 2. Build a new database
uv run dict-build run \
  --sources-dir /path/to/sources \
  --out-dir /tmp/dict \
  --emit sqlite \
  --room-identity-hash <hash-from-step-1>
# 3. Ship it as an asset
cp /tmp/dict/dictionary.db app/src/main/assets/dictionary.db
```

The schema version is **2** (`DictionaryDatabase`, `EntryEntity`). See `words/AGENTS.md` for how to obtain the pipeline sources (`uniparser` paradigms + `kaikki-Albanian.jsonl`).

## Design System (Tosk)

`:tosk` is a token-based Compose design system:

- **Primitive tokens** — `ToskSpacing`, `ToskBorderRadius`, `ToskBorderSize`, `ToskElevation`, `ToskFontSize`, `ToskLineHeight`, `ToskLetterSpacing`, `ToskPalette`, `ToskRippleAlpha`.
- **Semantic tokens** — `ToskColors`, `ToskTypography`, `ToskShape`.
- **Components** — `ToskButton`, `ToskCard`, `ToskTextField`, `ToskBadge`, `ToskChip`, `ToskTopAppBar`.
- **Theming** — `ToskTheme` provides light/dark color + typography via Compose `CompositionLocal`s.

`:toskdemo` is a standalone app that renders every component for visual review.

## Getting Started

### Prerequisites

- JDK 17+ (Detekt 1.23.8 requires **JDK 21**, not 25 — see below)
- Android SDK with platform 37 installed (`sdkmanager "platforms;android-37"`)

### Build

```bash
./gradlew :app:assembleDebug          # debug APK
./gradlew :app:bundleRelease          # release AAB
```

## Testing

### Unit tests (JUnit 5)

```bash
./gradlew :app:testDebugUnitTest
```

Tests live in `app/src/test/java/`, use descriptive backtick names (`` `given X, should Y` ``), and prefer fakes over mocks (e.g. `FakeEnglishToAlbanianOutputAdapter`).

### Instrumented tests

```bash
./gradlew connectedDebugAndroidTest
```

`DictionaryDatabaseAssetTest` and `SqliteEnglishToAlbanianOutputAdapterIntegrationTest` (in `app/src/androidTest/`) verify the bundled dictionary asset and FTS5 search on a real device/emulator. Requires a running emulator.

### Detekt

```bash
JAVA_HOME=<jdk-21> ./gradlew :app:detekt
```

Run with JDK 21 — Detekt 1.23.8 is incompatible with JDK 25.

### E2E & screenshot regression (Maestro)

`.maestro/` contains Maestro flows (`home_screen`, `translate_word`, `word_detail`, …) that drive the app on an emulator and capture screenshots. `.maestro/screenshot_test.sh` runs the flows, crops the system UI, and pixel-diffs the results against baselines with ImageMagick (default threshold 100 pixels).

Baselines are stored in **Cloudflare R2**, not git. CI downloads the latest `v*` tag's baselines before diffing.

```bash
./.maestro/screenshot_test.sh                      # run and diff
./.maestro/screenshot_test.sh --update-baselines   # refresh baselines after intentional UI changes
```

The app is fully offline (bundled dictionary), so the flows run against the plain `debug` build with no network service involved.

## CI/CD

GitHub Actions workflows under `.github/workflows/`, running on Shipfox runners with a KVM-accelerated emulator (Pixel_6, API 36):

- **`ci.yml`** — `unit-tests`, `detekt` (currently disabled), and `screenshot-tests` (downloads baselines from R2, runs Maestro flows, uploads diffs as artifacts). Results are also pushed to R2 via a composite action.
- **`update-baselines.yml`** — manual workflow that regenerates screenshot baselines and uploads them to R2 under a version tag.

## Release

Releasing to the Google Play Store is automated in `scripts/release.sh` + `fastlane` (`android release` lane → `gradle bundleRelease` + `fastlane supply` to the production track).

- **Signing keystore** is stored in Dashlane and fetched at release time by the Dashlane CLI (`dcli`) — base64 keystore note + a JSON note with `KEYSTORE_PASSWORD`/`KEY_ALIAS`/`KEY_PASSWORD`. The keystore only ever exists in a temp dir, cleaned up on exit (ADR 009).
- **Play Store upload auth** uses GCP CLI Application Default Credentials with the developer's personal account (`gcloud auth application-default login --scopes=openid,email,cloud-platform,androidpublisher`) — no service-account JSON persisted on disk (ADR 008).
- The four env vars can also be supplied explicitly to override Dashlane (for CI/local paths).

```bash
./scripts/release.sh
```
